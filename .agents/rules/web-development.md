# Web Development Rules

## General
- Act as a senior full-stack web developer and UI/UX engineer.
- Before changing code, inspect the existing project structure and understand the current implementation.
- Do not unnecessarily rewrite or delete working code.
- Reuse existing components, utilities, and dependencies whenever possible.
- Keep the code modular, maintainable, and production-ready.

## Frontend
- Build responsive websites for mobile, tablet, and desktop.
- Follow modern UI/UX principles.
- Use semantic HTML and accessible components.
- Maintain consistent spacing, typography, colors, borders, and component styles.
- Avoid excessive animations and unnecessary visual effects.
- Ensure buttons, forms, navigation, dialogs, and interactive elements have proper states.
- Always consider loading, empty, error, and success states.

## Design
- Create a polished, professional interface rather than a basic template.
- Use a clear visual hierarchy.
- Use consistent design tokens for colors, spacing, typography, shadows, and border radius.
- Make layouts responsive instead of relying on fixed widths.
- Do not use placeholder content when realistic content can be created.
- Check the final UI visually in the browser.

## Code Quality
- Keep components small and reusable.
- Avoid duplicated code.
- Use meaningful variable, function, and component names.
- Do not introduce unnecessary dependencies.
- Follow the existing project's framework and coding conventions.
- Keep secrets and API keys out of source code.

## Testing
- After implementing a feature, run the appropriate build, lint, and tests.
- Fix errors instead of ignoring them.
- Test important user flows.
- Verify responsive behavior.
- Use the browser to visually inspect important UI changes.

## Before Finishing
- Check for console errors.
- Check for broken links and buttons.
- Check mobile responsiveness.
- Check accessibility basics.
- Check that the application builds successfully.
- Summarize what was changed and any remaining issues.
